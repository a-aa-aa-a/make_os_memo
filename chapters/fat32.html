ファイルシステム

FAT32

FAT32は、USBメモリやSDカードなどで広く使われてきたファイルシステムです。 自作OSでは、FAT32を実装すると、ストレージ上のファイルを読み込んだり、 カーネルや設定ファイルなどをファイルとして扱ったりできるようになります。

目次

    1. FAT32とは

    FAT32は、ディスクを「ファイル」と「ディレクトリ」として管理するための ファイルシステムです。ディスク上にファイルを置くとき、ファイルのデータが どの位置に存在するのか、どのクラスタが次に続くのかなどの情報を管理します。

    FAT32では、ディスクを固定長の「クラスタ」という単位に分割して管理します。 ファイルは1個以上のクラスタを使用し、複数のクラスタにまたがる場合はFAT （File Allocation Table）によってクラスタのつながりを追跡します。

    2. FAT32のディスク構造

    FAT32のボリュームは、大まかに次のような領域に分かれています。 

    +-------------------------+
| Reserved Region         |
|  - Boot Sector          |
|  - FSInfo               |
+-------------------------+
| FAT #1                  |
+-------------------------+
| FAT #2                  |
+-------------------------+
| Data Region             |
|  - Root Directory       |
|  - Files / Directories  |
+-------------------------+

    重要なのは、FAT32ではファイルの実データがFATそのものに保存されている わけではないという点です。FATは、データ領域にあるクラスタ同士のつながりを 管理するための表です。

    3. ブートセクタとBPB

    ボリュームの先頭には、FAT32の構造を知るための情報が入っています。 その中心となるのがBPB（BIOS Parameter Block）です。

    BPBには、1セクタの大きさ、1クラスタあたりのセクタ数、予約領域のセクタ数、 FATの数、FATのサイズ、ルートディレクトリの開始クラスタなど、 ボリュームを解析するために必要な情報が格納されています。 

    struct fat32_bpb {
    uint16_t bytes_per_sector;
    uint8_t  sectors_per_cluster;
    uint16_t reserved_sectors;
    uint8_t  fat_count;
    uint32_t sectors_per_fat;
    uint32_t root_cluster;
};

    実際のFAT32 BPBには、この例より多くのフィールドがあります。 自作OSでは、まず必要なフィールドを正しく読み取り、ボリュームの各領域を 計算できるようにすることが重要です。

    4. セクタとクラスタ

    FAT32を理解するときは、「セクタ」と「クラスタ」を区別する必要があります。 セクタはストレージ装置から読み書きする基本単位で、クラスタはFAT32が ファイルの領域を管理する単位です。

    例えば、1セクタが512バイトで、1クラスタが8セクタなら、1クラスタは 4096バイトになります。 

    1 sector    = 512 bytes
8 sectors   = 1 cluster
1 cluster   = 4096 bytes

    5. FATの役割

    FAT（File Allocation Table）は、クラスタの次にどのクラスタが続くかを 記録します。つまり、大きなファイルが複数のクラスタに分割されていても、 FATをたどることでファイルの全データを読み出せます。

    例えば、あるファイルがクラスタ10、25、26、40を使用している場合、 FATには概念的に次のような情報が入ります。 

    FAT[10] = 25
FAT[25] = 26
FAT[26] = 40
FAT[40] = END

    そのため、ファイルの最初のクラスタが分かれば、FATを順番に参照して ファイル全体のクラスタ列を取得できます。

    6. クラスタ番号からセクタを求める

    FAT32では、データ領域のクラスタ番号から実際のセクタ位置を計算します。 データ領域の先頭セクタを first_data_sector とすると、 基本的には次のように考えられます。 

    first_sector_of_cluster =
    first_data_sector +
    (cluster - 2) * sectors_per_cluster;

    クラスタ番号2がデータ領域の先頭クラスタとして扱われるため、 cluster - 2 となります。

    7. ルートディレクトリ

    FAT32では、ルートディレクトリも通常のディレクトリと同じように データ領域のクラスタを使用します。BPBからルートディレクトリの開始 クラスタを取得し、そのクラスタからディレクトリエントリを読み取ります。

    ディレクトリエントリには、ファイル名、属性、サイズ、最初のクラスタなどの 情報が記録されています。 

    Directory Entry
+----------------------+
| File name             |
| Attribute             |
| Time / Date           |
| First cluster         |
| File size             |
+----------------------+

    8. ファイルを読み込む流れ

    自作OSでFAT32上のファイルを読む場合、概ね次の順番で処理します。

    1. ストレージデバイスからFAT32の先頭セクタを読む
    2. BPBを解析する
    3. 予約領域、FAT領域、データ領域の位置を計算する
    4. ルートディレクトリを読み込む
    5. 目的のファイルのディレクトリエントリを探す
    6. ファイルの開始クラスタを取得する
    7. FATをたどってクラスタ列を取得する
    8. 各クラスタのデータを読み込む
    9. ファイルサイズまでを有効なデータとして扱う

    9. 自作OSでの実装イメージ

    FAT32ドライバを作るときは、最初から書き込みまで実装する必要はありません。 まずは「FAT32を認識してファイルを読む」ことを目標にすると、 ストレージドライバとファイルシステムの役割を分離して考えやすくなります。 

    void fat32_init(block_device_t *device)
{
    // 1. Boot Sector / BPBを読む
    // 2. FAT32であることを確認する
    // 3. 各領域の開始位置を計算する
    // 4. root clusterを取得する
}

int fat32_open(const char *path)
{
    // ディレクトリをたどってファイルを探す
    return 0;
}

size_t fat32_read(int fd, void *buffer, size_t size)

    10. ストレージドライバとの関係

    FAT32そのものは、SSDやHDD、USBメモリなどの物理デバイスを直接操作する 仕組みではありません。自作OSでは、下位層のストレージドライバが 「指定したLBAのセクタを読む」という機能を提供し、その上でFAT32ドライバが ファイルシステムを解釈する構成にできます。 

    アプリケーション
       ↓
ファイルAPI
       ↓
FAT32ドライバ
       ↓
ブロックデバイスAPI
       ↓
SATA / NVMe / USB Mass Storage
       ↓
ストレージデバイス

    このように層を分けると、FAT32側は「セクタを読める」というインターフェース だけを利用でき、下位のデバイスが変わってもファイルシステムのコードを 大きく変更せずに済みます。

    11. 実装するときのロードマップ

    1. ブロックデバイスからセクタを読む
    2. FAT32のBPBを解析する
    3. FATの位置とデータ領域を計算する
    4. ルートディレクトリを読む
    5. 短いファイル名のディレクトリエントリを解析する
    6. FATチェーンをたどってファイルを読む
    7. サブディレクトリに対応する
    8. ロングファイルネームに対応する
    9. 必要になったらファイル作成・書き込みに対応する

    12. まとめ

    FAT32を実装するうえで重要なのは、「BPBからボリューム構造を知る」、 「ディレクトリエントリからファイルを見つける」、「FATからクラスタの つながりをたどる」という3つの処理です。

    自作OSでは、まず読み込み専用のFAT32ドライバを完成させ、 kernel.bin などのファイルをストレージから読み込めるようにすると、 ファイルシステムの基本的な仕組みを確認しやすくなります。
